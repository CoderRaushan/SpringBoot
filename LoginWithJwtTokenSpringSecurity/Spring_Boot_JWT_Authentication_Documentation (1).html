Spring Boot JWT Authentication — Complete Step-by-Step Documentation

Project: SpringSecurityAuthentication Author reference: Coder.Raushan Stack: Spring Boot 4.1.0, Spring Security, Spring Data JPA, Spring OAuth2 Resource Server (JWT encode/decode), MySQL, Lombok, Java 21

Ye documentation waise hi hai jaise poora project step-by-step bana ho — pom.xml dependency se lekar har class, har function, DB setup aur Postman testing tak. Isko follow karke koi bhi bande same JWT authentication server bana sakta hai.

1. Project ka Overview

Ye ek stateless JWT authentication server hai jisme: - User /api/users/register pe register hota hai (username + password) - User /api/user/auth/login pe login karta hai aur JWT access token milta hai - Baaki saare endpoints protected hote hain — unhe access karne ke liye Authorization: Bearer <token> header chahiye - JWT generate aur validate karne ke liye jjwt jaisi koi external library nahi use hui — Spring Security ke apne spring-boot-starter-oauth2-resource-server module ke andar available Nimbus JOSE JWT encoder/decoder use hua hai (HMAC-SHA256 signing ke saath)

High-level Flow

TEXT
Register  -> POST /api/users/register  -> User table me save (password BCrypt encoded)
Login     -> POST /api/user/auth/login -> AuthenticationManager verify karta hai -> JwtService token banata hai
Protected -> Koi bhi other endpoint    -> Request header me "Authorization: Bearer <token>" chahiye
            -> Spring's OAuth2 Resource Server filter token verify karta hai (JwtDecoder)
            -> Token ke andar "authorities" claim se roles nikal ke SecurityContext me daal deta hai

Property-by-property samajh:

  • jwt.expiry — Token kitne seconds me expire hoga (900 = 15 minutes)

Zaroori: Roles table me data manually daalna

AuthService registration ke time "ROLE_USER" naam ka role DB me dhundta hai (roleRepository.findByName("ROLE_USER")). Agar wo role table me exist nahi karega to registration fail ho jayega (NoSuchElementException).

Isliye app ek baar run karo (tables auto-create ho jayenge Hibernate se), phir MySQL me manually insert karo:

SQL

INSERT INTO role (name) VALUES ('ROLE_ADMIN');

Table ka actual naam Hibernate kaise generate karta hai wo check kar lena (role ya roles ho sakta hai naming strategy ke hisaab se) — SHOW TABLES; chala ke confirm kar lo.

7. Step 5 — Entity Classes

7.1 Entity/User.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.Entity;

import jakarta.persistence.*;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

import java.util.HashSet;
import java.util.Set;

@Entity
@Getter
@Setter
@NoArgsConstructor
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true)
    private String username;

    @Column(nullable = false)
    private String password;

    private boolean enabled = true;

    @ManyToMany
    @JoinTable(
            name = "user_roles",
            joinColumns = @JoinColumn(name = "user_id"),
            inverseJoinColumns = @JoinColumn(name = "role_id")
    )
    private Set<Role> roles = new HashSet<>();
}

Kya kar raha hai: - @Entity — Ye class ek DB table banegi - @Id + @GeneratedValue(IDENTITY) — auto-increment primary key - username unique aur not-null - password DB me BCrypt encoded save hoga (plain text kabhi nahi) - roles — User aur Role ke beech Many-to-Many relation, jo user_roles naam ki join table se maintain hota hai (do columns: user_id, role_id)

7.3 Entity/CustomUserDetails.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.Entity;

import org.jspecify.annotations.Nullable;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;

import java.util.Collection;
import java.util.List;

public class CustomUserDetails implements UserDetails {

    private User user;

    public CustomUserDetails(User user) {
        this.user = user;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return user.getRoles()
                .stream()
                .map(role -> new SimpleGrantedAuthority(role.getName()))
                .toList();
    }

    @Override
    public @Nullable String getPassword() {
        return user.getPassword();
    }

    @Override
    public String getUsername() {
        return user.getUsername();
    }

    @Override
    public boolean isEnabled() {
        return user.isEnabled();
    }
}

Kya kar raha hai: Spring Security apna authentication UserDetails interface pe based hota hai — humara khud ka User entity is interface ko directly implement nahi karta, isliye ye ek wrapper/adapter class hai jo humare User entity ko Spring Security ke UserDetails contract me convert karti hai: - getAuthorities() — User ke roles ko GrantedAuthority list me convert karta hai (Spring Security authorization ke liye ye use karta hai) - getPassword() / getUsername() — DB se aaya encoded password aur username return karta hai - isEnabled() — Account active hai ya nahi

package Coder.Raushan.SpringSecurityAuthentication.repository;

import Coder.Raushan.SpringSecurityAuthentication.Entity.User;
import org.springframework.data.jpa.repository.EntityGraph;
import org.springframework.data.jpa.repository.JpaRepository;

import java.util.Optional;

public interface UserRepository extends JpaRepository<User, Long> {
    @EntityGraph(attributePaths = "roles")

}
  • JpaRepository<User, Long> extend karne se CRUD methods (save, findById, delete, etc.) free me mil jaate hain
  • findByUsername — Spring Data JPA method-naming convention se automatically query generate hota hai (SELECT * FROM user WHERE username = ?)
  • @EntityGraph(attributePaths = "roles") — N+1 query problem avoid karne ke liye; roles (jo @ManyToMany hone ki wajah se lazy-loaded hota hai by default) ko same query me eager-fetch kar leta hai

10. Step 8 — Service Layer

10.1 service/CustomUserDetailsService.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.service;

import Coder.Raushan.SpringSecurityAuthentication.Entity.CustomUserDetails;
import Coder.Raushan.SpringSecurityAuthentication.Entity.User;
import Coder.Raushan.SpringSecurityAuthentication.repository.UserRepository;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;

@Service
public class CustomUserDetailsService implements UserDetailsService {

    UserRepository userRepository;

    public CustomUserDetailsService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByUsername(username)
                .orElseThrow(() -> new UsernameNotFoundException("User not found"));
        return new CustomUserDetails(user);
    }
}

Kaam: Spring Security ka UserDetailsService contract implement karta hai. Jab bhi login ke time authentication hoga, Spring internally loadUserByUsername() call karega — DB se user dhundh ke CustomUserDetails wrapper me return karega. Agar user na mile to UsernameNotFoundException throw hota hai.

10.2 service/AuthService.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.service;

import Coder.Raushan.SpringSecurityAuthentication.Entity.Role;
import Coder.Raushan.SpringSecurityAuthentication.Entity.User;
import Coder.Raushan.SpringSecurityAuthentication.dto.UserRegisterRequestDto;
import Coder.Raushan.SpringSecurityAuthentication.dto.UserRegisterResponseDto;
import Coder.Raushan.SpringSecurityAuthentication.repository.RoleRepository;
import Coder.Raushan.SpringSecurityAuthentication.repository.UserRepository;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;

@Service
public class AuthService {

    private UserRepository userRepository;
    private RoleRepository roleRepository;

    private PasswordEncoder passwordEncoder = new BCryptPasswordEncoder();

    public AuthService(UserRepository userRepository, RoleRepository roleRepository) {
        this.userRepository = userRepository;
        this.roleRepository = roleRepository;
    }

    public UserRegisterResponseDto registerUser(UserRegisterRequestDto registerRequestDto) {
        User user = new User();
        user.setUsername(registerRequestDto.getUsername());

        String encodedPassword = passwordEncoder.encode(registerRequestDto.getPassword());
        user.setPassword(encodedPassword);

        user.setEnabled(true);

        Role role = roleRepository.findByName("ROLE_USER").get();
        user.getRoles().add(role);

        userRepository.save(user);

        UserRegisterResponseDto responseDto = new UserRegisterResponseDto();
        responseDto.setUsername(user.getUsername());
        responseDto.setMessage("User Registered Successfully!");

        return responseDto;
    }
}

Kaam: Registration ka business logic: 1. UserRegisterRequestDto se username/password uthata hai 2. Password ko BCryptPasswordEncoder se hash karta hai (plain text kabhi save nahi hota) 3. ROLE_USER role DB se fetch karke user ko assign karta hai 4. User ko DB me save karta hai 5. Success response return karta hai

Improvement tip (optional): roleRepository.findByName("ROLE_USER").get() direct .get() use kar raha hai jo agar role missing ho to NoSuchElementException dega. Better hoga .orElseThrow(() -> new RuntimeException("Default role not found")) use karna — clearer error message ke liye.

10.3 service/JwtService.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.service;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.oauth2.jwt.Jwt;
import org.springframework.security.oauth2.jwt.JwtClaimsSet;
import org.springframework.security.oauth2.jwt.JwtEncoder;
import org.springframework.security.oauth2.jwt.JwtEncoderParameters;
import org.springframework.stereotype.Service;

import java.time.Instant;
import java.util.List;

@Service
public class JwtService {
    private JwtEncoder jwtEncoder;

    public JwtService(JwtEncoder jwtEncoder) {
        this.jwtEncoder = jwtEncoder;
    }

    @Value("${jwt.issuer}")
    private String issuer;

    @Value("${jwt.expiry}")
    private Long expiry;

    public String generateToken(Authentication authentication) {
        Instant now = Instant.now();

        List<String> authorities = authentication.getAuthorities()
                .stream()
                .map(GrantedAuthority::getAuthority)
                .toList();

        JwtClaimsSet claims = JwtClaimsSet.builder()
                .issuer(issuer)
                .issuedAt(now)
                .expiresAt(now.plusSeconds(expiry))
                .subject(authentication.getName())
                .claim("authorities", authorities)
                .build();

        Jwt jwt = jwtEncoder.encode(JwtEncoderParameters.from(claims));

        return jwt.getTokenValue();
    }
}

Kaam: Login success hone ke baad ye actual JWT token banata hai: - issuer, issuedAt, expiresAt, subject (username), aur custom claim authorities (roles list) — ye sab claims JWT ke payload me jaate hain - jwtEncoder.encode(...) — Spring Security ka JwtEncoder bean (jo SecurityConfig me define hoga) in claims ko sign karke ek signed JWT string bana deta hai - Ye token client ko LoginResponseDto me return hota hai

11. Step 9 — config/SecurityConfig.java

Ye pura project ka sabse important file hai — yahan security rules, JWT encoder/decoder, aur authentication setup define hota hai.

JAVA
package Coder.Raushan.SpringSecurityAuthentication.config;

import Coder.Raushan.SpringSecurityAuthentication.service.CustomUserDetailsService;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.ProviderManager;
import org.springframework.security.authentication.dao.DaoAuthenticationProvider;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.*;
import org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationConverter;
import org.springframework.security.oauth2.server.resource.authentication.JwtGrantedAuthoritiesConverter;
import org.springframework.security.web.SecurityFilterChain;

import javax.crypto.SecretKey;
import javax.crypto.spec.SecretKeySpec;
import java.util.Base64;

@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public DaoAuthenticationProvider authenticationProvider(
            CustomUserDetailsService userDetailsService,
            PasswordEncoder passwordEncoder
    ) {
        DaoAuthenticationProvider provider = new DaoAuthenticationProvider(userDetailsService);
        provider.setPasswordEncoder(passwordEncoder);
        return provider;
    }

    @Bean
    public SecurityFilterChain securityFilterChain(
            HttpSecurity httpSecurity,
            DaoAuthenticationProvider provider,
            JwtAuthenticationConverter jwtAuthenticationConverter
    ) {
        httpSecurity.csrf(csrf -> csrf.disable())
                .authenticationProvider(provider)
                .authorizeHttpRequests(auth ->
                        auth.requestMatchers("/api/users/register", "/api/user/auth/login").permitAll()
                                .anyRequest().authenticated()
                )
                .sessionManagement(session ->
                        session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .oauth2ResourceServer(oauth2 ->
                        oauth2.jwt(jwt ->
                                jwt.jwtAuthenticationConverter(jwtAuthenticationConverter)));

        return httpSecurity.build();
    }

    @Bean
    public SecretKey jwtSecretKey(@Value("${jwt.secret}") String secret) {
        byte[] decodedKey = Base64.getDecoder().decode(secret);
        return new SecretKeySpec(decodedKey, "HmacSHA256");
    }

    @Bean
    public AuthenticationManager authenticationManager(
            DaoAuthenticationProvider authenticationProvider
    ) {
        return new ProviderManager(authenticationProvider);
    }

    @Bean
    public JwtAuthenticationConverter jwtAuthenticationConverter() {
        JwtGrantedAuthoritiesConverter authoritiesConverter = new JwtGrantedAuthoritiesConverter();
        authoritiesConverter.setAuthoritiesClaimName("authorities");
        authoritiesConverter.setAuthorityPrefix("");

        JwtAuthenticationConverter authenticationConverter = new JwtAuthenticationConverter();
        authenticationConverter.setJwtGrantedAuthoritiesConverter(authoritiesConverter);
        return authenticationConverter;
    }

    @Bean
    public JwtEncoder jwtEncoder(SecretKey secretKey) {
        return NimbusJwtEncoder
                .withSecretKey(secretKey)
                .algorithm(MacAlgorithm.HS256)
                .build();
    }

    @Bean
    public JwtDecoder jwtDecoder(SecretKey secretKey, @Value("${jwt.issuer}") String issuer) {
        NimbusJwtDecoder decoder = NimbusJwtDecoder
                .withSecretKey(secretKey)
                .macAlgorithm(MacAlgorithm.HS256)
                .build();

        decoder.setJwtValidator(JwtValidators.createDefaultWithIssuer(issuer));
        return decoder;
    }
}

Bean-by-bean samajh (ye sabse zaroori part hai):

Bean Kaam
passwordEncoder() BCryptPasswordEncoder — password hash/verify karne ke liye
authenticationProvider() DaoAuthenticationProvider — CustomUserDetailsService se user load karke passwordEncoder se password match karta hai. Ye login authentication ka core logic hai
securityFilterChain() Poori HTTP security policy define karta hai:
• CSRF disable (kyunki ye stateless REST API hai, cookies use nahi ho rahe)
• /api/users/register aur /api/user/auth/login — publicly accessible (permitAll())
• Baaki sab endpoints — authenticated hona zaroori
• SessionCreationPolicy.STATELESS — koi HTTP session store nahi hoga, har request apna token khud carry karegi
• oauth2ResourceServer().jwt(...) — incoming requests ke Authorization: Bearer <token> header ko automatically validate karne wala filter enable karta hai
jwtSecretKey() application.properties ke jwt.secret (Base64 string) ko decode karke ek SecretKey object banata hai — ye HMAC-SHA256 signing/verification ke liye use hoga
authenticationManager() AuthenticationManager bean — LoginController isse use karta hai username/password verify karne ke liye
jwtAuthenticationConverter() Jab koi request valid JWT ke saath aati hai, ye converter token ke authorities claim (jo humne JwtService me daala tha) ko Spring Security ke GrantedAuthority objects me convert karta hai — taaki @PreAuthorize jaise role-checks kaam karein. setAuthorityPrefix("") isliye hai kyunki humare roles already ROLE_ prefix ke saath store hain, Spring ka default SCOPE_ prefix add nahi karna
jwtEncoder() HMAC-SHA256 algorithm se JWT sign karne wala bean — JwtService isse use karta hai token generate karne ke liye
jwtDecoder() Incoming request ke token ko verify/decode karne wala bean — signature check karta hai aur issuer bhi validate karta hai (agar token ka issuer match na kare to reject)

12.2 controller/LoginController.java

JAVA
package Coder.Raushan.SpringSecurityAuthentication.controller;

import Coder.Raushan.SpringSecurityAuthentication.dto.LoginRequestDto;
import Coder.Raushan.SpringSecurityAuthentication.dto.LoginResponseDto;
import Coder.Raushan.SpringSecurityAuthentication.service.JwtService;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/user/auth")
public class LoginController {

    private AuthenticationManager authenticationManager;
    private JwtService jwtService;

    public LoginController(AuthenticationManager authenticationManager, JwtService jwtService) {
        this.authenticationManager = authenticationManager;
        this.jwtService = jwtService;
    }

    @PostMapping("/login")
    public LoginResponseDto login(@RequestBody LoginRequestDto loginRequestDto) {
        Authentication authenticationReq = UsernamePasswordAuthenticationToken.unauthenticated(
                loginRequestDto.getUsername(),
                loginRequestDto.getPassword()
        );

        Authentication authentication = authenticationManager.authenticate(authenticationReq);

        String token = jwtService.generateToken(authentication);
        return new LoginResponseDto(token);
    }
}

Kaam (login ka poora flow): 1. Client se username + password aata hai request body me 2. UsernamePasswordAuthenticationToken.unauthenticated(...) — ek “raw”/unverified authentication request object banata hai 3. authenticationManager.authenticate(...) — Internally DaoAuthenticationProvider chalta hai → CustomUserDetailsService.loadUserByUsername() call hota hai → DB se user milta hai → PasswordEncoder se password compare hota hai. Match nahi hua to exception (401) 4. Agar authenticate ho gaya to Authentication object (jisme username + authorities/roles hain) milta hai 5. jwtService.generateToken(authentication) — Us authentication se JWT bana ke return 6. Client ko { "accessToken": "<jwt>" } response milta hai

15. JWT Token ke Andar Kya Hota Hai (samajhne ke liye)

Token 3 parts ka hota hai, dots (.) se separated: header.payload.signature

Payload (decode karo jwt.io pe) kuch aisa dikhega:

JSON
{
  "sub": "raushan",
  "authorities": ["ROLE_USER"],
  "iss": "coder.raushan",
  "exp": 1730000900,
  "iat": 1730000000
}
  • sub — subject, yani username
  • authorities — roles list (JwtService ne add kiya tha)
  • iss — issuer (jwt.issuer property se)
  • iat / exp — issued-at aur expiry timestamps (Unix epoch seconds)

Jab bhi protected request aati hai, JwtDecoder bean is signature ko jwtSecretKey se verify karta hai — agar signature match nahi hui (token tamper hua) ya exp nikal gaya ya iss mismatch hua, to request 401 ke saath reject ho jaati hai.

17. Recap — Poori Cheez Ek Nazar Me

  1. pom.xml — Security, JPA, OAuth2 Resource Server, MySQL driver, Lombok dependencies
  2. application.properties — DB connection + JWT secret/issuer/expiry
  3. Entities (User, Role) — DB tables, Many-to-Many relation
  4. CustomUserDetails — User entity ko Spring Security ke format me adapt karta hai
  5. Repositories — DB se data fetch karne ke interfaces
  6. DTOs — Request/response ka shape
  7. CustomUserDetailsService — Login ke time DB se user load karta hai
  8. AuthService — Registration logic (password encode, role assign, save)
  9. JwtService — Login success ke baad token generate karta hai
  10. SecurityConfig — Sab kuch wire-up karta hai: password encoder, authentication provider/manager, JWT encoder/decoder, aur security filter chain (kaun se endpoints public hain, kaun se protected)
  11. Controllers — register, login, aur ek protected hello endpoint
